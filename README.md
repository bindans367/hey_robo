# SIT Tumakuru Humanoid Robot Offline Campus Assistant

A **100% offline**, voice-interactive conversational AI assistant built for a **Humanoid Robot** deployed at **Siddaganga Institute of Technology (SIT), Tumakuru**.

---

## 🌟 Key Capabilities

1. **Offline Campus Assistant**: Speech recognition and SIT answers run locally. Optional Indian English neural speech uses an internet connection; the installed Windows voice remains available offline.
2. **Offline Speech Recognition (STT)**: Uses cached Faster-Whisper `tiny.en` (CPU int8) for low-latency English transcription, with Vosk retained for wake-word detection and fallback. STT loads lazily once, so dashboard TTS cannot disable later recognition. Capture adapts to room noise, waits for pauses up to 1.45 seconds, converts the selected microphone's native rate/width into mono 16 kHz PCM, and avoids a second aggressive VAD pass that could clip quiet syllables. Online mode can use Gemini's transcription model with SIT vocabulary hints; if it fails, recognition falls back to local Whisper.
3. **Speech Synthesis (TTS)**: The dashboard can select Indian English neural voices or the local Windows SAPI voice, with adjustable pace, pitch, and volume. Acronym pronunciation expansion is supported. Neural speech sends text to Microsoft for synthesis and needs internet; system voice works offline.
4. **Pronunciation & Accent Robustness**:
   - Handles Karnataka/Indian English accents, colloquial phrasing, and speech-to-text acoustic mistranscriptions (e.g. *"safety"* $\rightarrow$ *"SIT"*, *"bella auditor young"* $\rightarrow$ *"Birla Auditorium"*, *"principle"* $\rightarrow$ *"Principal"*, *"hall sean"* $\rightarrow$ *"Halcyon"*).
   - Multi-tier matching using **RapidFuzz** (`token_set_ratio`, `partial_ratio`), phonetic normalization, 680+ curated phrase variants, and local retrieval across the crawled SIT page corpus. Reviewed FAQ answers are phrased for natural spoken conversation.
5. **Data Ingestion Pipeline**:
   - Ingests official pages directly from `sit.ac.in`.
   - Ingests college PDF brochures, circulars, syllabi, and handbooks dropped into `data/documents/`.
6. **Dual Interaction Modes**:
   - **Voice Mode**: Continuous microphone listening and vocal response for live humanoid robot interaction.
   - **Text Mode**: Interactive terminal / touchscreen keyboard interface for testing and quiet environments.

## 🚀 How to Run

Activate the Python virtual environment first:
```powershell
.\venv\Scripts\Activate.ps1
```

### Robo Brain Control Panel
Start the local dashboard to update answers, try student questions, speak pasted scripts, change voice delivery, choose offline or online answering, and review history:
```powershell
python robo_brain.py
```
Then open `http://127.0.0.1:8765`. Keep this window running while using the panel. The microphone bot reads answer and voice changes as it runs; knowledge edits take effect on its next question. Open `http://127.0.0.1:8765/eyes` in a second tab for Robo’s full-screen animated eye display. Click **Full Screen** (or press **F**) to expand it; it follows live listening, thinking, and speaking status from the control panel.

To deploy only the standalone eye display to Vercel, use the `eye-site` folder as the project root; its [deployment instructions](eye-site/README.md) include the commands. A static Vercel page cannot reach the Python service on this computer’s `127.0.0.1` address, so it needs a separate public HTTPS status endpoint for live synchronization.

Dashboard edits are also recorded in `data/knowledge_dashboard_state.json`, so additions, corrections, and deletions persist if the reviewed knowledge builder is run later.

The **Conversation flow & microphone** card controls Robo's single opening greeting, wake phrases, stop phrases, farewell, thank-you response, misunderstanding response, listen/phrase timeouts, post-answer sleep delay, microphone device index (`-1` means Windows default), microphone sensitivity, mood, and optional campus-safe humor. These values are saved in `data/robo_settings.json` and the running voice bot reloads them between listening turns. The Overview page has a live activity feed with the last recognized transcript and current answer, plus an interrupt button while speech is playing. Offline transcription is utterance-based, so the feed displays the transcript after a student finishes speaking. The bot now takes an OS-level single-instance lock, preventing separate dashboard launches from opening multiple microphones and speaking duplicate answers. **Script to speech** can save and reload up to 200 reusable scripts in `data/robo_saved_scripts.json`. Use **Knowledge base** to add/correct/remove SIT facts, **Voice & AI settings** for voice and offline/online mode, and **Conversation history** to review what Robo heard and said.

Robo Brain has three separate answer modes. **Offline SIT answers** uses only the curated local knowledge matcher. **Local AI** sends requests to the configured local model endpoint (default Ollama at `http://127.0.0.1:11434/v1`, model `qwen3:0.6b`). **Cloud AI** sends requests to the configured cloud endpoint (the Gemini preset fills the Gemini-compatible endpoint and model). The selected mode never silently falls back to another mode; it reports setup or connection errors instead. Local and cloud models can use the relevant matched SIT answer as grounding context, but only the selected model generates the response. To install Qwen, install Ollama and run `ollama pull qwen3:0.6b`; leave Ollama running before choosing Local AI. For Gemini, choose Cloud AI, select Google Gemini API, paste your AI Studio key, save, and select **Test cloud model**. A custom OpenAI-compatible endpoint and model can also be entered in the panel. Model settings and API keys are stored in `data/robo_settings.json`; API keys are not returned to the browser. Speech synthesis is separate: Indian English neural voices still require internet even when the answer model is local. The control panel binds only to `127.0.0.1`.

### 1. Run Interactive Voice Mode (Default for Humanoid Robot)
```powershell
python bot.py
```
- Speaks greeting through the robot speaker.
- Speaks one short greeting at startup. While sleeping, it only responds to **“Hey Robo”**; a brief nonverbal chime acknowledges the wake phrase. Robo then listens for a question, answers, waits two seconds, and returns to sleep. It continues listening for the wake phrase until **“Robo stop”**.
- Detects student questions, matches topics, and answers verbally with visual face updates.
- Say *“Robo stop”* to terminate the assistant.
- By default, the bot follows the current Windows default microphone. To select a specific device, run `python bot.py --mic <device-index>` (use `python find_mic.py` to list/test inputs).

### 2. Run Interactive Text Mode (For Testing / Touchscreen)
```powershell
python bot.py --text
```
- Prompts for questions on the terminal.
- Answers in real-time and speaks the answer out loud.

### 3. Run Voice Mode with Push-to-Talk
```powershell
python bot.py --ptt
```
- Press Enter before each question. Use `python find_mic.py` to inspect available input devices; select one with `python bot.py --mic <device-index>`.
- To test microphone/STT without wake-word detection or Gemini, run `python test_mic_stt.py`. It guides you through normal English, Indian English, long and short questions, pauses, background noise, and low-volume speech. Select a device with `python test_mic_stt.py --mic <device-index>`.

### 4. Run Pronunciation & Accent Benchmark Test
```powershell
python bot.py --test
```
Runs 15 simulated accented/mistranscribed voice queries to verify 100% accuracy.

### 5. Ingest a College PDF Document
Place any PDF (e.g. `prospectus.pdf`, `rules.pdf`) into `data\documents\` or run:
```powershell
python ingest_pdf.py path\to\document.pdf
```
Or process all PDFs in `data\documents\`:
```powershell
python ingest_pdf.py --all
```

### 6. Refresh / Scrape Data from SIT Website
When connected to the internet, crawl linked public pages on `sit.ac.in` and refresh the local reference corpus. The reviewed answers in `knowledge.json` remain the concise voice responses; the corpus helps the matcher answer questions about additional pages:
```powershell
python bot.py --scrape
```
The crawler saves `data/sit_website_pages.json`. Restart the bot after refreshing so it loads the updated corpus.

Department detail questions such as “CSE labs,” “EEE faculty,” or “Civil placements” use `data/sit_departments.json`. Refresh the website corpus first, then rebuild the department profiles:
```powershell
python bot.py --scrape
python data/build_departments.py
```
The profile builder reads SIT's public department pages and records each page URL as its source. When SIT does not publish a department-specific item, the bot says so instead of guessing.

## 🤖 Recommended Humanoid Robot Deployment Tips

1. **Microphone Setup**:
   - Use a directional USB boundary microphone or noise-cancelling microphone array placed near the robot's chest or head.
   - Select the desired microphone as the Windows default input before starting the robot, or pass `--mic <device-index>` to `bot.py`. For a PowerShell session-wide override, run `$env:HUMANOID_MIC_DEVICE = "2"` before `python bot.py`.
2. **Speaker Placement**:
   - Place speakers away from the microphone to prevent audio feedback while the robot is speaking.
3. **Auto-Start on Boot**:
   - To make the robot launch automatically upon turning on the humanoid, add a shortcut to `bot.py` in Windows Startup folder:
     `shell:startup`
     Target: `C:\Users\Admin\Desktop\Humanoid\venv\Scripts\python.exe C:\Users\Admin\Desktop\Humanoid\bot.py`


### Cloud demo on Render

This repository includes a Render Blueprint (render.yaml) for a free, password-protected demo of the Robo Brain dashboard. When creating the Blueprint, set ROBO_ADMIN_PASSWORD to a strong password; the browser login username is robo. The service binds to Render's assigned port and serves the same dashboard and text-question API. Browser speech uses the visitor's own device. Wake-word detection, local microphone capture, Windows voices, and a local Ollama model remain on the robot computer and cannot run on Render.

Render's free filesystem is temporary. Settings, history, edited answers, and saved scripts written by the demo can be lost when the service restarts or redeploys. Use the committed knowledge base for demo answers and do not treat the free service as the permanent source of truth. To synchronize the Vercel eye display with the demo, use the public, limited-status endpoint /api/eye-status as the eye page's status query parameter. This endpoint returns only the robot phase, without conversation text.
